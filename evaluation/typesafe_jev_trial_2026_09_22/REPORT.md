## Вывод

Скилл работает. На выбранных тестовых вопросах JEV точнее определял, какие источники искать. На 18 новых примерах в шести существующих категориях JEV получил **18/18**, текущий локальный классификатор — **10/18**. На 20 существующих контрольных примерах оба получили **20/20**.

Для подключения к обработке посетителей пока нужен отдельный эксперимент с поиском и конечными ответами: в этом испытании они не проверялись. Производственный код, настройки сайта и сервер не изменялись.

## Что именно сравнивалось

Сравнивались локальные `parse_query()` + `classify_query()` из `backend/rag_v2` и реальный API TypeSafe, вызванный через установленный скилл `typesafe-jev`.

Проверяемое решение — выбор одного маршрута: национальная норма, практическая инструкция, муниципальный акт, судебная практика, конкретный документ или изменения законодательства. Дополнительно JEV мог выбрать `unclear`: информации недостаточно. В существующем типе `QuestionClass` такой категории нет, поэтому три подобных примера выделены отдельно.

Исходные 20 вопросов взяты из `evaluation/rag_v2_golden_set.json`. Новые 21 вопрос написаны до вызовов API: по одному вопросу на RU/EN/KA для каждой из шести категорий и ещё три неопределённых обращения. Ожидаемые метки и исходные результаты сохранены в `cases.json`; контрольная сумма — в `manifest.json`.

Новые примеры намеренно проверяют возможные слабые места правил после изучения кода. Это целевой диагностический набор, а не случайная выборка посетителей. Метки новых примеров заданы автором испытания, независимая экспертная разметка не проводилась. Двадцать старых вопросов преимущественно проверяют поиск нормы и не представляют равномерного покрытия категорий.

Каждый API-запрос содержит только один тестовый вопрос, язык, одинаковую инструкцию и определения категорий. Ожидаемые ответы, результат локального классификатора и его промежуточные признаки в JEV не передавались. Инструкции не подстраивались по полученным ответам. Проверялась классификация `choice`; форматы `score` и `noul` в этот эксперимент не входили.

## Практические находки для настройки проекта

1. **Город в описании компании ошибочно меняет поиск национальной нормы.** На русской и грузинской формулировках «компания в Тбилиси; какова общегосударственная ставка НДС?» текущий классификатор выбирает муниципальные акты. JEV выбирает национальное законодательство. В коде наличие `locality` само по себе активирует местный маршрут. Проверяемое улучшение: учитывать, относится ли город к запрашиваемой норме или только к обстоятельствам пользователя.
2. **Муниципальные ставки Батуми распознаются неустойчиво.** Три новых вопроса о местной ставке для предприятий уходят в практическую инструкцию или национальную норму. JEV выбирает муниципальный акт на всех трёх языках. В текущем разборе список городов ограничен; русское слово «муниципалитет» дополнительно содержит сочетание «ип», которое может дать ложный признак физического лица. Проверяемое улучшение: согласовать распознавание муниципалитетов и границы сокращений субъектов.
3. **Запрос судебных прецедентов не обязательно содержит слово «спор» или «решение».** «Найди судебную практику…», `court precedents` и грузинская формулировка о судебной практике во всех трёх случаях уходят в национальную норму. JEV выбирает судебные дела. Проверяемое улучшение: расширить многоязычные признаки судебной практики с сохранением отдельного маршрута для общего порядка обжалования.
4. **Неопределённым обращениям требуется отдельное поведение.** Три вопроса вида «Помогите с этим» получают у JEV `unclear`. Добавлять это значение в существующий поток напрямую нельзя: нужны явная обработка уточнения и проверка совместимости контрактов.

Все различия доступны построчно в `results.json`, включая исходный вопрос, ожидаемый класс, признаки локального разбора, ответ JEV и распределение вероятностей.

## Подключение, задержка и расход

- 41 успешный запрос, каждый с HTTP **200**. Во всех ответах разрешилась модель **`jev-1.13.0`**; в запросах использовался алиас `jev-latest`.
- Медиана клиентского времени вызова: **1,875 с**, диапазон **1,550–2,530 с**. Это время включает запуск PowerShell, чтение ключа, сеть и обработку ответа; чистое время модели отдельно не измерено.
- Медиана локального разбора и классификации: **0,160 мс**. Измерение не включает загрузку Python. Эти два измерения описывают разный состав накладных расходов; общий срок ответа сайта не измерялся.
- API сообщил суммарно **27 196 входных** и **3 779 выходных токенов**. Денежная стоимость и счета аккаунта не проверялись.
- Все ответы прошли проверки наличия модели, допустимого класса, диапазона confidence, полного набора вероятностей, их суммы и соответствия выбранного класса максимальной вероятности.
- До успешного пилота две попытки первого вопроса завершились локальной сетевой ошибкой: HTTP-статус не получен. Вызов разрешённого API через стандартный механизм сетевого доступа затем прошёл успешно. Автоматических повторов не было. Лимит 41 в исходном manifest описывает запланированные успешные оценки; всего было 43 попытки, включая эти две ошибки транспорта.

Вероятности и confidence сохранены как оценки модели. Даже правильные ответы иногда имели невысокую уверенность: 0,43 для налога на имущество компании и 0,62 для местной ставки Дманиси. Этот набор не калибрует порог автоматического принятия решений.

## Как использовать результат

Для работы над проектом уже полезно применять JEV как вторую проверку спорных классификаций и источник примеров для регрессионных тестов. Найденные восемь различий дают конкретный список улучшений локального разбора без обязательного внешнего вызова при каждом обращении.

Если далее испытывать JEV внутри приложения, разумный следующий шаг — сравнение в параллельном режиме наблюдения с закреплённой моделью `jev-1.13.0`, без влияния на ответ посетителя. Для решения о подключении нужны независимо размеченные вопросы, качество выбранных документов и финальных ответов, задержка и поведение при недоступности API. Нужно отдельно проверить, достаточно ли исправления локальных правил для устранения найденных ошибок.

Результат **не измеряет** ускорение работы Codex, качество программного кода, юридическую достоверность ответов, качество поиска в реальном корпусе, текущую конфигурацию production или финансовый эффект. Повторные прогоны, устойчивость к враждебным инструкциям и нагрузка не проверялись.

## Артефакты и повторная проверка

- `cases.json` — зафиксированные вопросы, метки и локальная база сравнения.
- `manifest.json` — commit, контрольные суммы и протокол.
- `requests/` — точные запросы без секретов.
- `responses/` — ответы API и сведения о попытках.
- `results.json` — полные результаты и агрегаты.
- `experiment.py` — подготовка, ограниченный запуск и пересчёт результатов через helper скилла.

Пересчитать итог без сети и новых расходов:

```powershell
python -X utf8 evaluation/typesafe_jev_trial_2026_09_22/experiment.py summarize
```

Повторный запуск пропускает уже сохранённые успешные ответы. Полноценное новое испытание нужно сохранять отдельно, чтобы не перезаписывать этот снимок. API-ключ считывается штатным helper скилла из локального окружения; в артефактах ключ отсутствует.

Формат запросов и ответов проверен по официальным источникам: [TypeSafe Quick start](https://docs.typesafe.ai/introduction/quickstart), [API reference](https://docs.typesafe.ai/api). Фактический результат подключения и версия модели подтверждены локальными ответами API, а не примерами из документации.
