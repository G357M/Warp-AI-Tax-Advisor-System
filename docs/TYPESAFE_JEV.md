# TypeSafe JEV в tax-advisor.ge

## Работа Codex над проектом

Правило в корневом `AGENTS.md` закрепляет применение установленного скилла `typesafe-jev` при работе с семантической классификацией, маршрутизацией вопросов, категоризацией документов и ограниченными оценками по рубрике. Повторно просить пользователя включить скилл для таких задач не нужно.

1. Прочитать доступный `typesafe-jev/SKILL.md`; на текущей машине он находится в `C:/Users/ggris/.codex/skills/typesafe-jev/SKILL.md`.
2. Сформулировать конкретное решение и критерии до получения ответа. Для классификации предусмотреть `unclear`, для оценки — заданную шкалу.
3. Проверить небольшой синтетический или обезличенный набор, сопоставить ответ с фактами проекта и тестами. При совпадении задачи, версии модели и входных данных использовать уже сохранённые результаты.
4. Сохранить необходимые свидетельства: версия модели, HTTP-статус, ответ, вероятности, расхождения. Отделить рекомендацию JEV от принятого решения и проверенного результата.

JEV помогает проверять смысловые решения. Правовые выводы, арифметика, окончательные бухгалтерские проводки и разрешения на выпуск остаются в существующих процедурах. Если скилл или ключ недоступны, сообщить это и продолжить независимую работу без выдуманного результата проверки.

Контекст настройки Codex: [официальная документация AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Правило действует для этого репозитория; глобальные настройки других проектов не менялись.

## Подключение к приложению

`backend/rag_v2/jev_router.py` реализует серверный вызов официального API. Используется существующая зависимость `httpx`; отдельный SDK не нужен. Испытанная модель закреплена как `jev-1.13.0`. Обновление модели требует отдельной проверки, алиас `jev-latest` в настройке приложения отклоняется.

Маршрут вызова: public/authenticated query → `maybe_run_live_rollout()` → проверка области вопроса и готовых LegalAnswerContract → JEV для оставшихся допустимых вопросов → построение RAG trace → существующие проверки источников и ответа. Вызовы происходят только в `INFOHUB_RAG_V2_MODE=rollout`; старый путь и автономные offline-evaluations остаются без внешнего сервиса.

| Настройка backend | Значение по умолчанию | Назначение |
|---|---|---|
| `JEV_MODE` | `off` | `off`, `shadow` или `assist` |
| `TYPESAFE_API_KEY` | отсутствует | Секрет только backend |
| `JEV_MODEL` | `jev-1.13.0` | Закреплённая версия |
| `JEV_TIMEOUT_SECONDS` | `2.0` | Таймаут сетевой операции, допустимо 0,2–5 секунд |
| `JEV_MIN_CONFIDENCE` | `0.90` | Минимальные confidence и вероятность выбранной категории; снижать ниже 0,90 нельзя |

`off` полностью исключает вызовы. `shadow` получает и журналирует предложение JEV, сохраняя локальный маршрут. Это синхронный режим наблюдения: он тоже добавляет время внешнего вызова. `assist` применяет допущенный маршрут или возвращает уточняющий вопрос на RU/EN/KA, если допущена категория `unclear`.

В режиме `assist` допуск требует корректной схемы ответа, совпадения модели, допустимой категории, полной нормированной вероятностной модели, confidence и вероятности выбранной категории не ниже порога, отрыва от второго варианта не менее 0,15. Это консервативные инженерные ограничения; они ещё не откалиброваны на реальном трафике.

Сохраняются существующие маршруты для точной статьи, пункта, документа, номера спора и общего порядка обжалования. JEV не выдумывает идентификатор документа или неизвестный муниципалитет: при отсутствии нужного локатора используется текущий маршрут. Он также не исправляет другие поля локального парсера. Поэтому результаты изолированного испытания нельзя автоматически приписывать всему приложению.

Без ключа, при низкой уверенности, ошибке API, неправильном ответе или превышении лимита сервис сохраняет текущий маршрут. Одновременно допускаются два вызова на процесс backend; лишние запросы сразу идут по текущим правилам. После ошибки новые обращения к JEV в этом процессе приостанавливаются на 30 секунд. Повторов и перенаправлений нет. Предел вопроса — 2 000 символов, ответа API — 16 384 байта; длинный вопрос не обрезается, а обрабатывается прежним способом.

Провайдер получает только текущий вопрос и язык, без истории диалога, документов корпуса, идентификаторов пользователя и банковских данных из других подсистем. Сам вопрос может содержать введённые посетителем персональные данные: универсальное обезличивание текста здесь не реализовано. Ключ хранится в `SecretStr`, передаётся только в заголовке к фиксированному HTTPS endpoint и не входит в браузерные переменные. При активации следует согласовать это использование внешнего обработчика с опубликованной политикой сервиса.

В обычных логах событие `jev_routing` содержит режим, статус, категории, версию и confidence, без текста вопроса и тела ответа. Логи не доказывают правильность категории; для оценки нужен размеченный набор.

## Выпуск и откат

В согласованном выпуске 1 октября 2026 года production tax-advisor.ge прошёл включение `shadow` → `assist`; ключ установлен в защищённом окружении backend. Значение по умолчанию для новых установок остаётся `off`. Это зафиксированное состояние выпуска, а не автоматическая проверка текущего сервера: перед следующим выпуском повторно проверить режим, SHA, health и CI.

Первое включение: задать `TYPESAFE_API_KEY` в существующем защищённом окружении **backend**, `JEV_MODE=shadow` и пересоздать backend штатным процессом выпуска. Ключ Windows User environment, используемый скиллом, сам по себе не появляется на сервере. Проверить HTTP-соединение и события `observed` на разрешённых тестовых вопросах, затем сопоставить предложения с выбранными документами и конечными ответами.

Для участия в выборе источников установить `JEV_MODE=assist` после проверки режима наблюдения. Для немедленного возврата к прежней маршрутизации установить `JEV_MODE=off` и пересоздать backend. Данные БД и биллинга эта интеграция не меняет; миграция схемы не требуется.

Новый набор backend-тестов включён в существующий CI. Локальные проверки: `backend/tests/test_jev_router.py`, `backend/tests/test_jev_live_integration.py`, `backend/tests/test_config_contract.py`, существующие RAG v2 и LegalAnswerContract тесты. Тесты сетевых ошибок используют имитацию API и не расходуют токены.

## Свидетельства

При сквозной проверке исправлены два разрыва после классификации: семантический поиск теперь использует допущенный класс вопроса, а короткий фрагмент решения получает соседний контекст из того же документа. Для фрагментов короче 1 500 символов выбираются предыдущий и два следующих фрагмента; общий предел — 6 000 символов, исходное совпадение сохраняется. Ошибка БД оставляет исходный текст. Это не распространяется на поиск положений закона и не меняет правовые выводы. Отказ генератора сохраняет статус недостаточных доказательств и не получает статистику, создающую видимость подтверждённого ответа.

Проверки выпуска разделяют маршрутизацию, наличие официальных источников, содержательный ответ и регрессии точных положений закона. Метка `grounded` и отсутствие отказа сами по себе не доказывают юридическую правильность пересказа. Сохранять итоговые отчёты проверок без текстов документов, пользовательских вопросов из реального трафика и секретов.
