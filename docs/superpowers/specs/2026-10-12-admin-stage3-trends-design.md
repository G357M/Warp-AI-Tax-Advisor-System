# Админка, этап 3: динамика — дизайн

Дата: 2026-10-12. Статус: дизайн принят автономно по поручению Гелы
(«начинай и продолжай сам»); решения ниже приняты исполнителем и могут быть
пересмотрены при ревью PR.

## Контекст и цель

Дашборд `/admin` (этап 1) показывает срез «сейчас»: сколько пользователей,
подписок, сообщений за 7 дней, что требует внимания. Сводка качества (этап 4)
показывает агрегаты за период. Ни то, ни другое не отвечает на вопрос
«растём или падаем»: выручка, новые пользователи, вопросы, качество ответов
во времени.

Этап 3 добавляет страницу `/admin/trends` («Динамика») с рядами по времени
и сравнением с предыдущим периодом. Существующая `/admin/analytics`
(статистика споров по корпусу) не меняется.

### Успех этапа

- На одной странице видно за выбранный период: выручку, оплаты, новых
  пользователей, вопросы, спрашивающих пользователей, оценки ответов,
  долю ответов с признаками проблем и медианное время ответа — по дням,
  неделям или месяцам, с изменением к предыдущему такому же периоду.
- Цифры совпадают с источниками: выручка — с успешными платежами,
  вопросы — с сообщениями пользователей, оценки — с `answer_ratings`.
- Аккаунты администраторов в цифры не попадают.
- Страница работает на RU/KA/EN, на мобильном и в стиле админки.

### Решения

- Только чтение: без новых таблиц, колонок и шагов в `deploy_production.sh`.
  Деплой — обычный `deploy.sh`.
- Периоды: `30d` — 30 дневных точек, `90d` — 13 недельных (неделя с
  понедельника), `12m` — 12 месячных. По умолчанию `30d`.
- Границы точек считаются по времени Тбилиси (`Asia/Tbilisi`, UTC+4 без
  перехода на летнее время). В базе время хранится как naive UTC.
- Последняя точка включает текущий день/неделю/месяц и помечается
  `partial: true`; на графике она отличается штриховкой.
- Сравнение: итог текущего окна против предыдущего окна, которое начинается
  на число точек периода раньше и длится столько же, сколько уже прошло в
  текущем окне (неполная последняя точка не даёт ложного падения).
- Аккаунты с `role = 'admin'` исключаются из всех показателей, включая
  платежи и оценки.
- Графики — собственный SVG без новых библиотек, как и остальная админка
  (решение этапа 1).

### Вне этапа 3

- История подписок по дням (сколько было активных pro/business в каждый
  день): таблица `subscriptions` хранит только текущее состояние, истории
  нет. Текущий срез остаётся на дашборде.
- Гостевая активность и воронка «посетитель → регистрация → оплата»:
  гостевые запросы не сохраняются.
- Когорты и удержание, экспорт в файлы, кэширование, произвольный период.
- Возвраты: проводятся вне системы, в выручке не отражаются.

## 1. Бэкенд

### Эндпоинт

`GET /api/v1/admin/trends?period=30d|90d|12m` в новом роутере
`backend/api/routes/admin_trends.py` с `dependencies=[Depends(require_admin)]`.
Неизвестный период → 422 (валидация `Literal`).

Ответ:

```json
{
  "period": "30d",
  "bucket": "day",
  "timezone": "Asia/Tbilisi",
  "quality_since": "2026-10-12",
  "median_processing_ms": 2000,
  "buckets": [
    {
      "start": "2026-09-13",
      "partial": false,
      "signups": 2,
      "askers": 1,
      "questions": 5,
      "payments": 1,
      "revenue_minor": 4900,
      "up": 0,
      "down": 0,
      "answers": 5,
      "answers_with_evidence": 0,
      "flagged": 0,
      "median_processing_ms": null
    }
  ],
  "totals": {
    "current": {"signups": 0, "askers": 0, "questions": 0, "payments": 0,
                "revenue_minor": 0, "up": 0, "down": 0},
    "previous": {"signups": 0, "askers": 0, "questions": 0, "payments": 0,
                 "revenue_minor": 0, "up": 0, "down": 0}
  }
}
```

Определения:

| Поле | Что считается |
|---|---|
| `signups` | `users.created_at` в точке, `role <> 'admin'` |
| `questions` | сообщения `role = 'user'` в диалогах не-админов |
| `askers` | число различных пользователей, задавших вопрос в точке; в `totals` — различные за всё окно, а не сумма точек |
| `payments`, `revenue_minor` | `payments.status = 'succeeded'`, подписка не-админа; сумма `amount_minor` (все платежи в GEL) |
| `up`, `down` | `answer_ratings` по `created_at` оценки, оценщик не-админ; текущая оценка, без истории изменений |
| `answers` | сообщения `role = 'assistant'` в диалогах не-админов |
| `answers_with_evidence` | из них с JSON-объектом в `evidence` |
| `flagged` | из `answers_with_evidence` — с хотя бы одним признаком `no_precise_citation`, `no_sources`, `not_grounded` или `slow` (те же условия, что в ленте качества) |
| `median_processing_ms` | медиана `processing_ms` ответов точки; `null`, если данных нет |
| `median_processing_ms` (верхний уровень) | медиана `processing_ms` всех ответов окна; `null`, если данных нет |
| `quality_since` | дата (Тбилиси) первого ответа с `evidence`; `null`, если таких нет |

### Реализация

`backend/core/admin_trends.py`:

- `window(period, now)` → список границ точек (начало каждой точки в
  локальном времени и их UTC-эквиваленты) для текущего окна и для
  предыдущего. Чистая функция, тестируется без базы.
- По одному агрегирующему запросу на источник (пользователи, вопросы,
  платежи, оценки, ответы) с группировкой по
  `date_trunc(<bucket>, created_at + interval '4 hours')` и фильтром по
  UTC-границам всего окна. Python раскладывает результаты по точкам,
  отсутствующие точки заполняются нулями.
- `askers` в `totals` — отдельный `count(DISTINCT user_id)` по окну.
- Признаки качества переиспользуют `_flag_condition` из
  `core/admin_quality.py` (вынести в публичное имя `flag_condition`).
- Сдвиг +4 часа задаётся одной константой `TBILISI_OFFSET` с комментарием:
  у Грузии нет летнего времени с 2005 года.

Нагрузка: на текущих объёмах (сотни сообщений) пять простых агрегатов по
индексированному `created_at`; кэш не нужен.

## 2. Фронтенд

### Навигация и страница

- Новый пункт меню «Динамика» / «დინამიკა» / «Trends» сразу после
  «Обзора», иконка из `@radix-ui/react-icons`.
- `frontend/app/admin/trends/page.tsx` через `useAdminFetch`.
- Переключатель периода — сегментированная группа кнопок
  (`30 дней`, `90 дней`, `12 месяцев`); выбор хранится в `?period=` URL,
  как фильтры ленты качества.

### Содержимое

1. Плитки (`StatTile`) с итогом окна и изменением к прошлому окну
   (`+12%`, `−3`, «нет данных» при нуле в прошлом окне):
   выручка (₾), оплаты, новые пользователи, вопросы, спрашивающие,
   доля 👍 среди оценок.
2. Панель «Выручка» — столбцы по точкам (₾).
3. Панель «Активность» — столбцы вопросов и линия спрашивающих.
4. Панель «Новые пользователи» — столбцы.
5. Панель «Качество ответов» — столбцы 👍/👎 (составные), линия доли
   ответов с признаками; под графиком медианное время ответа за окно.
   Точки до `quality_since` показываются пустыми с подписью «данные о
   качестве собираются с <дата>».

### Компонент графика

`frontend/components/admin/TrendChart.tsx`: SVG с `viewBox`, растягивается
по ширине панели; столбцы (одиночные или составные) и необязательная линия
по второй оси. Подписи оси X прореживаются, чтобы не накладывались.
Последняя частичная точка — полупрозрачная. У каждого столбца `<title>` с
точным значением. Для доступности: `role="img"` с `aria-label`-сводкой и
раскрывающаяся таблица значений («Показать данные»). Цвета — токены
админки и валидированная палитра (скилл dataviz), проверка контраста в
тёмной теме.

### Тексты

Новый блок `trends` в `admin-i18n.ts` на RU/KA/EN; грузинские тексты —
по скиллу georgian-writing-style. Деньги — `formatNumber` + `₾`.

## 3. Ошибки и пустые состояния

- Ошибка загрузки → `AdminState kind="error"` с повтором; при смене
  периода старые данные остаются видны до прихода новых (поведение
  `useAdminFetch`).
- Все нули → графики рисуются с нулевой осью и подписью «за период данных
  нет», без деления на ноль в процентах.

## 4. Тестирование

- `backend/tests/test_admin_trends.py` (без базы): границы окна для трёх
  периодов, понедельник как начало недели, переход через полночь Тбилиси
  (20:00 UTC), предыдущее окно.
- `backend/tests/test_admin_trends_postgres.py` (в CI-джобе с PostgreSQL):
  засеянные пользователи, вопросы, платежи (succeeded/failed), оценки и
  ответы с признаками в разных точках; проверка исключения админов, `askers`
  как различных, `partial`, `quality_since`, итогов прошлого окна; 403 для
  не-админа, 422 для неизвестного периода.
- `frontend/e2e/admin-trends.spec.ts`: мок API, переключение периода
  меняет `?period=` и запрос, таблица данных раскрывается, ошибки с
  повтором; визуальные эталоны `admin-trends-ru-desktop` и
  `admin-trends-ka-mobile` (снимаются в Linux-контейнере).
- Регистрация новых тестов в `.github/workflows/ci.yml` по образцу этапа 4.
